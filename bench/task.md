# Эталонная задача бенчмарка

Узел `A1` плана `.claude/plans/2026-08-27T20-36__dsh-local-qwen38-optimization.md`.

Единица измерения цикла улучшения — один прогон этой задачи в чистой сессии. Задача выбрана так, чтобы результат отделялся от «синтаксически валидного мусора» машинной проверкой (`bench/gate.mjs`), без участия человека и без суждения о стиле.

Спецификация ниже намеренно подробная. Мы меряем не способность модели угадать требования, а стоимость прохода харнеса: `wall`, `steps`, `tool_err`, `compactions`. Расплывчатая формулировка добавила бы к разбросу ещё и разночтения спецификации, и строку ledger стало бы нечем объяснить.

## Промпт агенту

Текст ниже подаётся агенту дословно, единственным сообщением.

---

Напиши плагин dsh по образцу установленного `@linxin666/dsh-pet` — он показывает состояние виртуального питомца.

Положи пакет в `./dsh-pet-lite/` относительно рабочего каталога. Требования:

1. Чистый ESM JavaScript, `"type": "module"` в `package.json`. Сборки нет — файл грузится как есть.
2. Никаких зависимостей, кроме встроенных модулей Node.
3. Форма плагина — функциональная: именованные экспорты `name`, `inject`, `apply`. Default-экспорта быть не должно: смешение двух форм заставляет загрузчик отбросить namespace функционального плагина.
4. `inject` содержит `'tools'`.
5. `apply(ctx)` регистрирует ровно один инструмент вызовом `ctx.tools.register(definition)`.
6. Определение инструмента:
   - `name`: `'pet_status'`
   - `description`: непустая строка
   - `parameters`: JSON Schema объекта без обязательных полей — `{ type: 'object', properties: {} }`
   - `output.schema`: `{ type: 'string' }`
   - `output.render(args, value)`: возвращает `[{ type: 'text', text: value }]`
   - `async execute(args, exec)`: читает JSON-файл `.dsh/pet.json` в домашнем каталоге и возвращает **строку** вида `«<имя> — visible»` или `«<имя> — hidden»`.

Правила формирования строки:

- `<имя>` — это `names[petId]`, если такой ключ есть, иначе сам `petId`;
- суффикс `visible`, если `display.visible` истинно, иначе `hidden`;
- разделитель — пробел, тире, пробел (` — `);
- домашний каталог берётся через `os.homedir()`, а не хардкодом пути.

Пример файла и ожидаемого результата:

```json
{ "petId": "otter", "names": { "otter": "Выдра" }, "display": { "visible": true } }
```

даёт строку `Выдра — visible`.

## Как проверяется результат

```sh
node bench/gate.mjs <путь-к-каталогу-пакета>
```

Гейт возвращает `0`, только если проходят все четыре проверки:

| # | Проверка | Что ловит |
|---|---|---|
| 1 | `load` — модуль импортируется | синтаксис, битые импорты |
| 2 | `protocol` — `name`+`apply`, `inject` содержит `tools`, нет default-экспорта | форма плагина |
| 3 | `register` — `pet_status` зарегистрирован и определение проходит контракт `ToolRuntime.register()` | форма определения инструмента |
| 4 | `execute` — вызов возвращает верную строку на двух фикстурах | реально читает файл, а не выдаёт константу |

Проверка 4 гоняется дважды, на фикстурах `bench/fixtures/visible` и `bench/fixtures/hidden`: они отличаются только полем `display.visible`. Плагин, зашивший ответ константой, проходит одну фикстуру и валится на второй.

Гейт не запускает dsh и не обращается к модели: обе фикстуры и реестр инструментов подставляются заглушками. Сквозная проверка «модель действительно вызвала `pet_status` в собранном приложении» — работа прогонщика (узел `A4`), а не этого файла.

### Почему не через `--dump-config`

Исходная формулировка гейта в плане предполагала проверку композиции через `dsh --profile bench --dump-config`. Этот путь отвергнут: `runDumpConfig` (`apps/cli/src/dump-config.ts:30`) складывает патч-слои алгоритмом include-плагина **без загрузки и без вычисления `!!js`**, то есть модуль плагина не резолвится и не исполняется. Такая проверка прошла бы на пакете, которого нет на диске.

## Контрольные образцы

Гейт проверяется на заведомо известных пакетах — иначе он сам ничем не подтверждён:

- `bench/reference/dsh-pet-lite` — рабочий эталон, гейт обязан вернуть `0`;
- `bench/broken/no-load` — синтаксическая ошибка, падает проверка 1;
- `bench/broken/no-apply` — нет `apply`, падает проверка 2;
- `bench/broken/mixed-export` — есть и `apply`, и default-экспорт, падает проверка 2 ([постмортем](../docs/postmortem/0001-acp-default-export-drops-inject.md));
- `bench/broken/dead-tool` — инструмент зарегистрирован, но отвечает константой, падает проверка 4.

Прогон всех пяти сразу:

```sh
node bench/gate.mjs --self-test
```
