## Новые ловушки — не переоткрывать

- **Headless-поверхность агентные пресеты не монтирует вообще.** Потребители `agentPresets` — только `host/apiproxy`, `client/ui-agent-preset`, `subagent/child-agent`. `agent-presets.default` из `settings.yaml` на `dsh --profile bench` не влияет. Рычаги ведутся `--patch` оверлеями в `bench/overlays/`, не пресетами.
- **Вставка строки в патч-слое — ключ `insert` со списком.** Запись с `id` целится в существующую строку; для отсутствующего id загрузчик пишет `patch: entry "<id>" not found` в stderr и молча ничего не монтирует. Читать stderr `--dump-config`, он туда и пишет.
- **`--dump-config` не резолвит модули** (`apps/cli/src/dump-config.ts:30`) — как проверка существования плагина бесполезен.
- **`dsh` пишет в каталог профиля на каждом старте** (`prepareProfile` переписывает `cordis.yml`), поэтому под песочницей падает с `EROFS`. Запуски `dsh` — только с host-escalation.
- **Пакеты `@deepseek-ai/dsh-*` резолвятся из любого профиля** через общий фоллбэк `~/.dsh/profiles/node_modules`; из произвольного каталога (например `~/.dsh/bench-workspace`) — нет. Поэтому эталонная задача требует нулевых зависимостей.
- **Стандартный пресет контрибутит строки инструментов**, а не реестры. Включать его поверх headless нельзя — столкнётся с уже смонтированными.
