## 2. Метод решения каждой категории

### 2.1. `CallId → ToolCallId` (пагины `dsh-rlm-mode`, `relay-dsh-plugin-claude`, `relay-dsh-plugin-codex`)

**Симптом:** `SyntaxError: The requested module '@deepseek-ai/dsh-llm' does not provide an export named 'CallId'` на этапе host boot.

**Решения по возрастанию сложности:**

1. **Пропатчить плагин вручную** (sed заменяет `CallId` на `ToolCallId`). Работает, но **опасно**: ломает логику, если в плагине есть чтение сериализованного состояния.
2. **Дождаться upstream-обновления** (для `dsh-rlm-mode@0.1.6` это `0.2.0`, который на npm помечен `deprecated "published in error — superseded by 0.1.5, do not use"`. Реального 0.2.x с `ToolCallId` нет).
3. **Использовать версию с `Reflect.get(llm, "ToolCallId") ?? Reflect.get(llm, "CallId")`** — именно это делает `relay-dsh-plugin-claude@0.2.2` и `relay-dsh-plugin-codex@0.2.2`. Совместимы с обеими ветками (peer: `>=0.1.0-rc.5 <0.1.1 || >=0.1.1-rc.0 <0.2.0 || >=0.1.2-alpha.2 <0.1.3-0`).
4. **Исключить плагин** — крайний случай, если ничего не помогает.

**Что сделали:** `relay-dsh-plugin-claude` `^0.1.5` → `^0.2.2`, `relay-dsh-plugin-codex` `^0.1.5` → `^0.2.2`. `dsh-rlm-mode` — оставлен `^0.1.6` и **исключён из bundles** (решения 4).

### 2.2. `installSettingsSection → SettingsProvider` (пагины `dsh_plugin_ad`, `@linxin666/dsh-{doctor,skin-center,market,desktop-launcher,tool-describe-image,...}`)

**Симптом:** `SyntaxError: ... does not provide an export named 'installSettingsSection'`.

**Решения:**

1. **Исключить из `bundles`** (для плагинов с собственным кодом).
2. **`disabled: true` в `cordis.patch.yml`** — НО на уровне id loader **поздно**: ESM-импорт `lib/index.js` файла плагина происходит до того, как loader проверит disabled. Поэтому `disabled: true` спасает **только для client-бандлов**, не для host-бандлов.
3. **Shim `@deepseek-ai/dsh-settings`** — подложить noop-совместимый модуль в `web/node_modules/@deepseek-ai/dsh-settings/lib/index.js` (или в `apps/cli/node_modules/...` — туда, куда loader резолвит). Shim должен экспортировать `installSettingsSection(ctx, namespace, schema, defaults, opts)` как noop, возвращающий disposer; `settingsNamespace(name)` как `{ __dsh_settings_namespace: name }`.

**Что сделали:**
- Создан shim в `~/.dsh/profiles/web/node_modules/@deepseek-ai/dsh-settings/`.
- `apps/cli/node_modules/@deepseek-ai/dsh-settings` (симлинк на 0.1.2) **заменён** на симлинк на shim. **Важно:** `parentURL` для loader — это `apps/cli/...`, и Node идёт вверх по `node_modules` оттуда, а не от `web/`. Без замены симлинка в `apps/cli/node_modules/...` shim не подхватывался.
- 8 файлов в `dsh_plugins/dsh-web/packages/*/lib/index.js` пропатчены через `sed`: `from "@deepseek-ai/dsh-settings"` → `from "/home/uadmin/.dsh/profiles/web/node_modules/@deepseek-ai/dsh-settings/lib/index.js"`. **Абсолютный путь** обходит всю node_modules-резолюцию.
- `web-ui-doctor`, `web-ui-skin-center` отключены на id-уровне (на client.js та же проблема).

### 2.3. `dsh-client-runtime/client` удалён (8 linxin client-бандлов)

**Симптом:** `client-modules: require("@deepseek-ai/dsh-client-runtime/client") missed the module table — not a platform seed word, not a materialized module`.

**Решения:**

1. **Минимальная правка `packages/client/web/src/seed.ts` в deepseek-harness** — добавить `'@deepseek-ai/dsh-client-runtime/client': ClientRuntimeClient` в `getStaticModules()`. **1 строка кода**, но требует модификации monorepo.
2. **`disabled: true` для всех проблемных client-бандлов** в `cordis.patch.yml` — id-level disable, не путать с bundle disable.

**Что сделали:** решение 2 (без правки monorepo). Отключены 8 id: `web-ui-pet`, `web-ui-ssh`, `web-ui-describe-image`, `web-ui-desktop-launcher`, `web-ui-market`, `web-ui-dsh-aionui-panel`, `web-ui-settings`, `web-ui-chat-recovery`.

### 2.4. `dsh-host-apiproxy` удалён (`@linxin666/dsh-client-ui-{task-board,remote-web-ui}`)

**Симптом:** `2 entries did not activate ... pending (waiting for service: apiProxy)`.

**Решение:** `disabled: true` для id `web-ui-task-board`, `web-ui-remote-web-ui`.

### 2.5. Plugin-уровень (host) конфликты

**Решение:** исключить из `web/package.json#bundles` (не `disabled: true`, потому что `disabled` для bundle не предотвращает ESM-импорт). Убраны: `dsh-rlm-mode`, `dsh_plugin_ad`.

## 3. Ловушки и рефлексия

### 3.1. Stale artifacts (`lib/` от старой версии)

`pnpm install` НЕ пересобирает `lib/`. После `git checkout pin/dsh-...-rc.X` с другим коммитом, `lib/` от старой версии остаётся. `tsc -b` проходит, читая stale `lib/*.d.ts`, но бандлер падает на свежем `src/`. **Решение:** `pnpm run clean && pnpm install && pnpm run build` — **всегда** в этом порядке, при каждом переключении pin.

### 3.2. `dsh --branch=...` в start-web.sh — сама команда меняет ветку

Я добавил в `start-web.sh` строку `git checkout $BRANCH` для удобства. Но это **сам переключает** на pin-ветку, и каждый запуск **возвращает** на новый pin. Если нужно временно поработать в другой ветке — нужно передавать `DSH_BRANCH=...` явно. Без него — перезапуск = «уехали обратно на новую pin».

### 3.3. `disabled: true` vs исключение из `bundles`

| Уровень | `disabled: true` | Удаление из `bundles` |
|---|---|---|
| **bundle** (host import) | **Не работает** — ESM-импорт происходит до check. | **Работает** — node_modules не ставится, ESM-импорт не запускается. |
| **sub-bundle insert** (id level) | **Работает** — loader пропускает `entry.fiber = undefined`, но ESM-импорт host-lib уже произошёл. | Не применимо (id создаются через `insert:` другого bundle). |

**Правило:** для host-бандлов — `bundles`. Для sub-bundles (id) — `disabled: true`. Для client-бандлов (если `client.js` падает) — `disabled: true`.

### 3.4. id linxin-плагинов — `web-ui-*`, не `@linxin666/*`

В `cordis.patch.yml` от linxin: `- id: web-ui-settings, name: '@linxin666/dsh-client-ui-web-ui-settings'`. Namespace — `web-ui-*`, **НЕ** package name. Я сначала написал `id: web-ui-web-ui-settings` (с двойным префиксом) и `id: web-ui-tool-describe-image` (лишний `tool-`). Patch не сработал. Правильные id: `web-ui-settings`, `web-ui-describe-image`, `web-ui-dsh-aionui-panel` (да, с `dsh-` в середине — для aionui), `web-ui-doctor` и т.д. Сверять с `dsh_plugins/dsh-web/packages/dsh-web-all/cordis.patch.yml`.

### 3.5. Модуль-резолюция loader'а: `parentURL` ≠ `cwd`

`cordis-plugin-loader` использует `createRequire(import.meta.url)` от `loader/lib/index.js` (= `/mnt/.../vendor/loader/lib/index.js`). `parentURL` для импорта плагина — это **путь к `cordis.yml` или profile dir**, не cwd. Shim, подложенный в `web/node_modules`, **не виден** loader'у без правки `apps/cli/node_modules/@deepseek-ai/dsh-settings`. Симптом: `npm view ...` показывает правильную версию, `import()` от плагина работает, но loader падает.

**Тест:** запустить dsh с `DSH_SETTINGS_SHIM_TRACE=1` (если shim так написан) и проверить, видит ли trace строку. Если нет — симлинк не в той точке `node_modules`-дерева.

### 3.6. pnpm 11: `allowBuilds` — placeholder блокирует install

На первом `pnpm install` в **свежем** pin-профиле (`web-pin-dsh-...`) pnpm 11 вставляет `allowBuilds: { zeromq: set this to true or false }` и **отказывается** ставить zeromq. Симптом: `ERR_PNPM_IGNORED_BUILDS: Ignored build scripts: zeromq@6.7.0`. **Решение:** вручную `sed` заменить на `zeromq: false` (если пакет не используется) или `true` (если билд нужен). Или `pnpm approve-builds` интерактивно. Или зафиксировать в `start-web.sh` автоправку.

### 3.7. Auth: token-cookie flow в 0.1.2

В 0.1.2 dsh web требует `?token=<...>` при первом обращении, делает `303 See Other` на cookie-backed сессию, и **все последующие** запросы — с cookie `dsh-auth-VPhEEcLKeqRDBoBalzN2Nm7CnfxKhLE00pKIDWxt1sw`. `curl` без `?token=` отдаёт `401 Unauthorized` **всегда** — даже если cookie валидна. **Тест в браузере**: открыть URL с токеном → редирект → UI. В curl: `curl -sL -c cookies.txt 'http://localhost:3080/?token=...'` → 200 OK + cookies.

### 3.8. URL плагинов в 0.1.2: `??<id>&rev=...` (двойной `?`)

В 0.1.2 `__DSH_BOOT__.entries[*].url` имеет вид `/plugins/??@linxin666/dsh-web-all/client.js&rev=4a701d02c5a58388-47`. Это **новый формат**: `?` отделяет path от query, а `?` кодирует первый символ `@` в id (`?@linxin...` = encodeURIComponent(`@`) = `%40` идёт ПОСЛЕ `?`). То есть правильный URL — `/plugins/??@linxin...&rev=...` (с двойным `?`). Если руками набрать `/plugins/@linxin...` — `404 Not Found`.

### 3.9. symlink на `@deepseek-ai/dsh-llm` — общая для всех профилей

`~/.dsh/profiles/node_modules/@deepseek-ai/dsh-llm` — это симлинк на `apps/cli/node_modules/.../dsh-llm → packages/llm/llm`. **Один и тот же файл** для всех профилей. На 0.1.2 этот файл собран с `ToolCallId`, и **все** плагины, импортирующие `dsh-llm`, видят новый API. Если вернуться на 0.1.1-rc.2 — нужно пересобрать monorepo (rebuild обновит `lib/` в `packages/llm/llm/`), иначе будет расхождение source (0.1.1) vs lib (0.1.2).

```bash
# Поправить allowBuilds.zeromq: false если pnpm жалуется

# 8. Если boot падает на "missed export X" — это host-бандл.

# 9. Если boot OK, но клиент падает — id-level disable.

# 10. Если API 401 — curl -sL '...?token=...', сохранить cookie.
```
